# The blocking roster: the presubmit cases that can red a pull request on a
# graded failure (BOOTSTRAP_ADMITTED).
#
# One case id per line; `#` starts a comment, blank lines are skipped.
# hack/ci-eval-pr.sh reads this file at startup as the default of
# BOOTSTRAP_ADMITTED (an environment override still wins, for a laptop run)
# and refuses to start on a name that is not in presubmit-cases.txt: the
# roster is a subset of the presubmit by construction. The eval dashboard
# (scripts/eval_dashboard) reads the same file for its "blocking" pill.
#
# Since 2026-09-22 (#1023, the eval crew's call) the presubmit runs this
# roster and, as the one documented exception, the held-out seats a coverage
# tracker puts in presubmit-cases.txt without a name here (its last section;
# #2013 seated the compliance canary 2026-09-25): such a case runs on every
# pull request and, under the default EVAL_ADMISSION_MODE=roster, cannot red
# one on a graded failure. Every other held-out case is a nightly case
# (nightly-cases.txt carries each with its hold-out reason). The script
# still checks only the subset; the rest is policy, and
# scripts/test_eval_rosters.py pins it (HELD_OUT_IN_PRESUBMIT). An admission
# edits both files at once; a demotion moves the line from both to the
# nightly file.
#
# A case named here arms rung 4 -- three failed repetitions red the job --
# and, while the evidence store holds nothing for it at the current version
# key, leaves rung 6 quiet. Under the default EVAL_ADMISSION_MODE=roster this
# list is the whole answer to "which case can red a pull request on a graded
# failure"; the store's record beside it says whether the evidence agrees.
# The prose -- the admission bar, who is held out and on which issue, the
# rung scoping, the demotion protocol -- lives in docs/eval-gate-roster.md,
# deliberately: docs/ edits are inert to the eval, so a review finding
# against that prose costs no 2-hour run (#1179). Edit the list here, the
# prose there.
#
# WHO APPROVES. Adding or removing a name here changes what blocks, so
# hack/OWNERS puts this file under the eval-crew alias with no_parent_owners
# (#1546). Never add a case in the pull request that makes it pass
# (.agents/rules/eval_driven_development.md): a seat is earned on the
# record, which the verdict's "Record says" column reports per case.
#
# Demoting a flaky case is a same-day edit: delete its name here and its
# line from presubmit-cases.txt, add that line to nightly-cases.txt with the
# issue that names its re-admission condition as the # line above it, and
# cite what the record says about it. A held-out seat has no name here: it
# is withdrawn by moving its line from presubmit-cases.txt back to
# nightly-cases.txt, no roster edit.
