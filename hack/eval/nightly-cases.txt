# The nightly-only eval cases: what the nightly runs on top of the presubmit.
#
# One `./tasks/<id>/task.yaml` path per line, relative to bench/. `#` starts
# a comment, blank lines are skipped. hack/ci-eval-pr.sh reads this file at
# startup into NIGHTLY_TASKS and, under EVAL_TIER=nightly (exported by the
# Prow periodic ci-kube-agents-eval-nightly and nothing else), appends it to
# the presubmit matrix in this order, so the nightly is a superset of the
# presubmit by construction and a case in presubmit-cases.txt runs
# identically in both. The script refuses to start on a line that names no
# case directory or that is also in presubmit-cases.txt (it would run twice a
# night). The registration lint (scripts/validate_bench_cases.py) reads this
# file as well as the presubmit one; the domain-coverage lint reads only
# blocking-roster.txt, so neither an entry here nor a held-out presubmit
# seat counts as coverage. EVAL_NIGHTLY_PART in the script can split the
# nightly matrix between two periodics (its comment says how); unset, one
# job runs all of it, and the budget below prices that.
#
# WHO APPROVES. The normal approvers (root OWNERS). Only the presubmit files
# beside this one carry the eval-crew rule (#1546, decided 2026-09-15).
#
# WHAT BELONGS HERE. Every registered case that is not on the blocking
# roster and has a fixture. Since 2026-09-22 (#1023, the eval crew's call)
# the presubmit runs the blocking roster and nothing else, so this file is
# where a held-out case lives unless a coverage tracker seats it held out in
# the presubmit file instead (the exception section at the foot of
# presubmit-cases.txt: #2013, #2016): the seven cases the presubmit had been
# running without letting them block moved here that day, each with its
# hold-out reason as the # line above it (their own section of this file;
# six remain there). This is
# the default home for a new case too (decided 2026-09-15 on #1546 and
# #1564): it lands here, the nightly builds its record in the evidence
# store -- one data point a night, three repetitions -- and a presubmit
# seat, which outside the held-out section is a roster seat, is a later
# pull request that cites that record and edits both presubmit files at
# once. Measured cost, presubmit
# redundancy and grading something outside the core journeys keep a case
# here for good. The rule
# this file's predecessor carried -- a case that fails on a correct agent
# stays commented out because the nightly appends to the evidence store --
# is retired: a case that can only fail appends evidence that keeps it out
# of the presubmit, which is what the record is for, and the ~10 minutes of
# matrix it costs a night is bought back by the wider fan-out. The one case
# that stays out is one whose fixture does not exist at all; it waits in the
# validator's FIXTURE_NOT_READY allowlist with the issue that plants it;
# that allowlist is the list, and each entry says what it waits for.
