# The presubmit eval matrix: what every pull request runs -- since 2026-09-22
# the blocking roster, plus the held-out seats the last section names (one
# per coverage tracker: #2013, #2016).
#
# One `./tasks/<id>/task.yaml` path per line, relative to bench/. `#` starts
# a comment, blank lines are skipped. hack/ci-eval-pr.sh reads this file at
# startup into its TASKS array and refuses to start on a line that names no
# case directory; scripts/validate_bench_cases.py reads it too, so a case
# under bench/tasks/ that is in neither this file nor nightly-cases.txt
# fails the registration lint. Cases are NOT discovered; this list is the
# registration.
#
# WHO APPROVES. Adding or removing a line here changes what every pull
# request runs, so hack/OWNERS puts this file and blocking-roster.txt under
# the eval-crew alias with no_parent_owners: a root approver alone cannot
# merge an edit. nightly-cases.txt, a new case directory and the script
# itself need only the normal approvers (#1546, decided 2026-09-15).
#
# WHERE A NEW CASE GOES. nightly-cases.txt, always. Since 2026-09-22 (#1023,
# the eval crew's call) this file holds the BLOCKING roster and, in its last
# section only, the held-out seats: every entry above that section is also a
# line in blocking-roster.txt, and a case that cannot red a pull request does
# not run on one. The one exception is that held-out section: a coverage
# tracker may seat its candidate there without a roster line, to build its
# record at presubmit volume; it cannot red a pull request on a graded
# failure (rungs 1-3 still apply) and takes the roster line in a later edit. A
# seat outside that section is therefore a roster seat, earned on the
# nightly record -- one data point a night, three repetitions -- and never
# in the pull request that makes the case pass; a seat here for a case
# nobody has watched pass and fail is how a case that can only fail reds
# every pull request in the repository. The edit that
# admits a case adds its line to both files at once, and demoting one
# (docs/eval-gate-roster.md) moves its line back to nightly-cases.txt with
# the issue that names its re-admission condition as the # line above it.
# Before that date this file also ran held-out cases that reported without
# blocking; the seven that were here on 2026-09-22 moved to the nightly with
# their hold-out reasons (the record at the foot of this file).
# docs/designs/bench-case-format.md "Registration" is the rule. The
# commented-out parking state the TASKS array used to carry is retired: a
# `#` line in this file is a comment, never a registration, and the
# validator rejects a commented-out case path. A case whose fixture does not
# exist at all waits in the validator's FIXTURE_NOT_READY allowlist with the
# issue that plants it.
#
# ORDER. This list is the gate's REPORTING order. Execution order is the
# fan-out's cost-hinted queue in the script (unit_cost_hint, longest units
# first), so a Prow deadline kills whatever is still in flight rather than
# truncating this list's tail. A case known to be slow gets a unit_cost_hint
# entry in the script, not a position here.
#
# BUDGET. Fourteen cases, forty-two units at the script's EVAL_REPETITIONS
# of 3: six domain probes, one reliability prompt variation, three
# cluster-debugging cases, the incident-triage probe, the kanban smoke, and
# two held-out seats (the compliance canary, ~1000-2000s a repetition, and
# pdb-remediation-pr, 420-1929s measured, hinted at 1250; each seat's three
# repetitions serialize on its own task lock).
# Neither of the remediation domain's two writers holds a ROSTER seat --
# rca-remediation-pr was demoted 2026-09-02 (#1189), and the 2026-09-22
# promotion of pdb-remediation-pr was withdrawn before merge because its
# record was graded by the check #1780 replaced; its held-out seat
# below opened 2026-09-28 (#2016) -- so remediation sits on the
# docs/designs/domains.yaml allowlist beside fleet-audits until a roster
# line lands. The 2026-08-26
# smoke run (build 2092638061140643840, kube-agents-evals-3) measured what
# six full audits cost: obtainability-planted-pdb PASSED in 962s and
# compliance-rbac-overgrant in 606s, the three that failed did so on
# agent-endpoint HTTP 502s (transport, not scenario bugs), and the job's
# 85-minute deadline expired before rca-remediation-pr ever ran. Six domains
# at 600-1300s each do not fit one presubmit, so each audit domain is
# covered by a PROBE -- a targeted question about that domain's planted
# defect, graded on the reply, the shape cluster-agent-crashloop-debug
# proved at 142s. The one full audit kept here as the machinery canary
# (compliance-rbac-overgrant, under the fleet-audits domain) ran on every
# pull request from 2026-08-25 until 2026-09-22 without ever being admitted,
# was a nightly case 2026-09-22 to 2026-09-29 and is seated held out below
# since (#2013); fleet-audits stays on the docs/designs/domains.yaml
# allowlist until its roster line lands. The comment above EVAL_REPETITIONS
# in the script carries the measured history of that budget; recount the
# entries here rather than trusting any count in prose.
