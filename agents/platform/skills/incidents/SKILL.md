# Incidents Skill

This skill allows the Platform/Coding Agent to analyze Kubernetes events, categorize them into Incidents, and manage them in the filesystem.

## When to Use

- When monitoring a Kubernetes cluster for anomalies, warnings, or errors.
- When categorizing and grouping raw Kubernetes events into higher-level logical incidents for SRE review and automated resolution.

## Incident Schema

All incidents generated by this skill must follow this YAML schema:

```yaml
- id: <string>               # Unique deterministic ID (e.g. hash of involved object UID + class)
  title: <string>            # A short, descriptive title summarizing the incident
  class: <string>            # Category of the incident (e.g., NodeLifecycle, CrashLoop, OOMKilled)
  severity: <string>         # Severity level: Info, Warning, Critical
  status: <string>           # Incident state: Active, Resolved
  firstTimestamp: <string>   # UTC timestamp of first event (RFC3339 format)
  lastTimestamp: <string>    # UTC timestamp of last event (RFC3339 format)
  involvedObjects:           # List of Kubernetes objects involved
    - apiVersion: <string>
      kind: <string>
      namespace: <string>    # Namespace of the object (empty for cluster-scoped resources like Node)
      name: <string>
      uid: <string>
  events:                    # List of raw events associated with this incident
    - name: <string>
      uid: <string>
  description: <string>      # Detailed description of what occurred
```

## Categorization Rules

1.  **Node deletion due to absence in cloud provider:**
    -   When an event has `reason: DeletingNode` and a message stating that the node does not exist in the cloud provider, categorize it as:
        -   **Class:** `NodeLifecycle`
        -   **Severity:** `Info`
        -   **Status:** `Active`
        -   **Title:** `Node <name> deleted because it does not exist in the cloud provider`

## Evaluation Suite

The evaluation suite runs scenario tests defined under `agents/platform/tests/evals/testdata/`.
Each subdirectory represents a test scenario, containing:
- `events.yaml`: Input Kubernetes events.
- `_expectations.yaml`: Expected incident outcomes.

To run the evaluations locally:
```bash
make docker-build-platform
cd agents/platform/tests/evals && go test -v ./...
```
