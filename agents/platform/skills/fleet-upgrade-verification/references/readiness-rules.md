# The per-entry readiness rules

The rules `upgrade_readiness.EXTRA_RULES` runs after the PDB, webhook, maintenance and skew
rules of `fleet_upgrade_report.py --readiness`, one module each under `scripts/readiness_rules/`
(the package docstring is the contract). A blocker joins the member's verdict and prints under
`other blockers`; a risk never moves the verdict and prints under `risks`; each cell is
`<rule id>: <the rule's text>`, and a rule's note (what it read on a clean member) prints in the
note column behind the same prefix. The catalogue is the upgrade-failure catalogue in the
repository's design docs; an incident scenario is one of the support-case rules that reads a
project-level inventory.

| Rule id                         | Catalogue entry or incident scenario                                                       | Grade   | What it reads                                                                                                                                                                                                                       | The action in the finding                                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `control-plane-upgrade-history` | Entry 2, the control plane's side: an upgrade or repair that failed on compute capacity    | risk    | `gcloud container operations list` once per project: `DONE` `UPGRADE_MASTER`, `UPGRADE_NODES` or `REPAIR_CLUSTER` operations on the member in the last 90 days whose error names capacity; the cluster's `maintenancePolicy.window` | Set a maintenance window in an off-peak hour for the region and retry the upgrade in it; keep upgrade notifications consumed.                        |
| `cluster-status-age`            | Entry 5, read before the window: a cluster held by an operation that has not ended         | blocker | The cluster's `status` and, from the same operations list, the newest operation on the member; a status other than `RUNNING` for more than four hours blocks, a shorter one is noted; no operation listed at all blocks             | Freeze changes; past a few hours open a support case quoting the operation id (the `gke-upgrades` skill's "Stuck operation" section).                |
| `target-patch-valid`            | Entry 10, the version side: a target or running patch the channel no longer serves         | blocker | `gcloud container get-server-config` once per location: the member's target against its channel's `validVersions` and `validNodeVersions` (blocker), its running control-plane version against the channel's `validVersions` (risk) | Target the newest active patch of the minor on the channel at or above the version, else the next active version the channel lists.                  |
| `known-issues-matrix`           | Entry 10, at patch granularity: a published add-on issue at the running or target patch    | risk    | The DaemonSets and Deployments in `kube-system` and `gmp-system` (the reads the report makes; `addons` in the JSON) against `scripts/known_issues.json`; the table's age and its newest known version against the server config     | Target the patch the issue names as fixed, or hold; regenerate a stale table before trusting a clean matrix.                                         |
| `zonal-control-plane`           | Entry 11: the control plane is unreachable for minutes on a zonal cluster                  | risk    | The cluster's `location`: a zone is a zonal control plane                                                                                                                                                                           | Schedule the control-plane upgrade in a maintenance window and have API clients retry with backoff; only a regional cluster keeps the API available. |
| `lb-connection-draining`        | Entry 21: a backend service whose connection drain outlasts the node's deregistration wait | blocker | `gcloud compute backend-services list` once per project: each backend on the member's `nodePools[].instanceGroupUrls` or on a NEG its Services annotate, with `connectionDraining.drainingTimeoutSec` above 600                     | `gcloud compute backend-services update <name> --global\|--region <region> --connection-draining-timeout=600`.                                       |
| `orphan-node-objects`           | Entry 22: a Node object that outlives its virtual machine                                  | blocker | `gcloud compute instances list` once per project against the member's Nodes (`spec.providerID`'s zone and instance name); the note counts nodes against instances on every member                                                   | `kubectl delete node <name>`.                                                                                                                        |

A failed project or location read is an error row under the table (exit 1), and the rules that
need it say `unknown`; a rule that can block then leaves the member `unknown`, one that cannot
is reported in the note. The three list reads are projected to the fields the rules use, so a
project of a few thousand instances stays under the credential proxy's output cap; a list the
proxy cut is the same error, naming the cap.
