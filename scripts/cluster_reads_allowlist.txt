# Whole-cluster kubectl reads under agents/ that were there when
# scripts/check_cluster_reads.py arrived, pinned at the count each file had
# that day. One entry per line: `<path> <rule> <count> <reason>`, the path
# relative to the repository root, the rule as the check reports it
# (`multi-kind-dump`, `unpaged-list` or `unresolved-kinds`), the count above
# zero, the reason the rest of the line.
#
# The list only shrinks for the `multi-kind-dump` and `unpaged-list` reads it
# was born with. The check fails when a file has more findings than its entry
# (a rise), when it has fewer (lower the count, or remove the entry once the
# file is clean), when an entry names a file the check does not scan, repeats
# a file and rule, names another rule, or is not an entry. A file with no
# entry is held at zero, so a new whole-cluster dump anywhere is a failure,
# never a new line here. The one addition the list takes is an
# `unresolved-kinds` read the check cannot classify because its kind is a
# runtime value (a configured list, a discovered CRD), when the read is one
# kind per call and bounded or falls back when the broker cuts it; the
# check's own hint names that route, and the entry's reason says how the
# read is bounded.
#
# Every `multi-kind-dump` and `unpaged-list` read below is one the pagination
# conversion of the collectors and the SOPs replaces with a paged or per-kind
# read; such an entry leaves this file when its read is converted.
# `python3 scripts/check_cluster_reads.py --counts` prints the first three
# fields for the tree as it stands.
