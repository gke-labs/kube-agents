Two further keys are read from the same Secret: SESSION_KV_API_KEY and
SESSION_KV_SALT. Without them the agent still starts, but the in-pod
k8s-event-watcher exits on every start and NO cluster events are watched, the
pod-local Session KV server rejects every request, and identity pseudonyms are
not stable across restarts. See the chart README.

For GCP access, bind your Google Service Account to the agent's KSA
"{{ .Values.platformAgent.security.serviceAccountName }}" via Workload Identity
(see the chart README).

NOTE — uninstalling: the PlatformAgent custom resource carries a finalizer that
only the operator can clear. Delete the PlatformAgent and wait for it to go
away BEFORE `helm uninstall {{ .Release.Name }}`, otherwise the CR strands:

  kubectl delete platformagent {{ .Values.platformAgent.name }} -n {{ .Release.Namespace }} --wait
  helm uninstall {{ .Release.Name }} -n {{ .Release.Namespace }}
{{- end }}
