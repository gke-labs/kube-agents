# Who owns what

This page answers who to ask about a part of the repository, and who owns a running service the
project depends on. It does not grant anything. Who may set `approved` and
`lgtm` on a change is `OWNERS`, `hack/OWNERS` and `OWNERS_ALIASES`, and a person can be an area's
owner here without being an approver there.

An area is a part of the system in plain words, with the paths that are most of it; a running
service or a role is an area with no key paths. A path under several key paths belongs to the most
specific area; a path under none is unowned, and any `OWNERS` approver answers for it. **Primary** is the person to ask first and the reviewer to
request on a change that reshapes the area. **Backup** covers when the primary is out; an empty
backup means there is none, and the fallback is again any `OWNERS` approver. Names are GitHub logins without the `@`, as
`owner:` in a bench case writes them. `unowned` is an honest entry: the row has no owner yet, and
anyone picking up work there may claim it.

To change a row, open a pull request; the primary of the row you are changing reviews it, or any
`OWNERS` approver if the row is `unowned`. `scripts/test_ownership.py` checks that every path
in the table still exists, every login in the primary and backup columns is in `OWNERS`, every
top-level entry in `AGENTS.md`'s Repository Layout is among some area's key paths, and no primary
is blank.
