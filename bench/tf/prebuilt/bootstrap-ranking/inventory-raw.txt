## Prioritized SRE Remediation Plan

### Priority 1 — Security & Identity Hardening

- `billing/invoice-worker` mounts a static service account key for a project-editor service account
  from the Secret `invoice-gcp-key`. Anyone who can read that Secret holds editor on the project. Move
  the workload to Workload Identity and delete the key. (severity: high)
- The ClusterRoleBinding `ci-cluster-admin` grants `cluster-admin` to the ServiceAccount
  `ci/release-bot`, whose token is mounted into the running `release-bot` pod. Anything that runs
  code in that pod controls the whole cluster. Bind a namespaced Role with only the verbs the
  release job uses. (severity: high)

### Priority 2 — Workload Reliability & Probes

- `shop/quote-api`, the only replica of a serving Deployment, is in CrashLoopBackOff: its container
  is OOMKilled at its 256Mi limit and has restarted 47 times, so the service has no ready endpoint.
  Raise the memory limit or fix the leak. (severity: high)
- `shop/pricing-engine` has 0 of 2 replicas running: both pods are stuck in
  CreateContainerConfigError because the ConfigMap `pricing-rules` they read does not exist, so the
  service has no ready endpoint. Restore the ConfigMap. (severity: high)
- `shop/gift-cards` has no readinessProbe, so a replica still warming up receives traffic. Add one.
  (severity: medium)
- `data/orders-db` sets memory requests but no memory limit, so it can take memory from its
  neighbours until the node evicts them. Set a limit. (severity: medium)

### Priority 3 — Observability & Telemetry

- Managed Service for Prometheus is not enabled on `prod-central`; nothing collects workload metrics.
  Enable it. (severity: low)
